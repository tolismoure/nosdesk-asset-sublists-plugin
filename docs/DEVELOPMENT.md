# Development, checks and release packaging

## Supported source

Use official Nosdesk v1.1.0 commit b4d3f2162972ba6e420ea10d16ca0fdcafeb8ac2 in a separate directory. Never apply development replacements to a live checkout without reviewing the guarded plan. This repository vendors only its overrides/fixtures, not the full upstream project.

Use Node 24 for the plugin/frontend checks, npm lockfiles for the two plugins and SQL fixture suite, and Python 3 for installer/package checks. The full upstream frontend uses its pnpm workspace lockfile. Docker is required for the disposable full-schema Rust checks.

## Plugin checks and generated bundles

~~~bash
cd plugin
npm ci
npm test
npm run build
cd ../asset-history/plugin
npm ci
npm test
npm run build
cd ../..
git diff --exit-code -- plugin/payload/bundle.js asset-history/plugin/payload/bundle.js
~~~

After a deliberate source change, review and commit the rebuilt payload. The reproducibility check should then show no diff when rebuilding again. Manifests are canonical installer inputs, not generated by esbuild. Asset Sublists 2.1.0 should register only nav.item; its reusable controller may still support legacy context in tests without registering an asset panel.

## Python and SQL checks

~~~bash
python3 -m unittest discover -s tests -p 'test_*.py'
python3 -m unittest discover -s asset-history/tests -p 'test_install*.py'
cd asset-history/tests/sql
npm ci
node --test history.test.mjs
~~~

The SQL checks use in-memory PostgreSQL/PGlite and do not contact a server. They execute the delivered query/migration/trigger fixture, but the representative schema does not replace complete Nosdesk integration. History installer tests mock Docker state; they do not deploy.

## Complete frontend validation

~~~bash
python3 frontend-extension/apply.py /path/to/nosdesk --check
python3 frontend-extension/apply.py /path/to/nosdesk
python3 asset-history/apply.py /path/to/nosdesk --check
python3 asset-history/apply.py /path/to/nosdesk
cd /path/to/nosdesk
corepack enable
pnpm install --frozen-lockfile
pnpm --filter nosdesk-frontend type-check
pnpm --filter nosdesk-frontend build-only
pnpm --filter nosdesk-frontend exec vitest run src/plugins/assetHistoryApi.spec.ts src/plugins/assetHistoryService.spec.ts src/plugins/assetHistorySandbox.spec.ts
~~~

Changes to saved-list/editor behavior belong in frontend-extension/frontend/src/views/AssetCategoriesView.vue. Release packaging copies that canonical file into the updater. Changes to shared catalog/model functions should keep plugin/src/model.mjs and the frontend model aligned, including the declaration file.

## Full-schema history verification

After applying both guarded extensions to the pinned source:

~~~bash
bash asset-history/verify-server.sh /path/to/nosdesk
~~~

The helper builds history-tests, starts a unique disposable PostgreSQL 18 project with tmpfs and no published ports, then runs the ten history Rust tests. Its cleanup operates only on that project. Never substitute a production TEST_DATABASE_URL. The manual History server checks GitHub workflow runs the same helper without contacting a deployment.

## Packages

~~~bash
python3 tools/package-release.py
~~~

The three dist archives contain canonical source and unsigned payloads. The updater includes the main plugin payload/source automatically; it is not maintained as a second independent plugin copy. Sign on the target instance with its supported CLI. Do not publish signed local installers or private keys.

## CI and maintenance

Push/pull-request checks cover both plugins, Python guards/progress, SQL fixtures and the complete frontend bridge/build. The manual Docker workflow covers the expensive full Rust/PostgreSQL path. Check the actual workflow result before claiming a revision passed.

When changing a source replacement, record its exact previous delivered hash only if that delivery is intentionally compatible. New host tags require a new reviewed baseline. Preserve namespaced field IDs, plugin identities, storage keys, permission gates, pagination scope and licensing notices. Avoid comments that claim stronger coverage/authorization than the code implements.
